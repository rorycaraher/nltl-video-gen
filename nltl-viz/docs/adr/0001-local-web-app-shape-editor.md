# Local web app for the shape editor, with a default-persisted shapes file

`nltl-viz shapes edit` needs a 2D pointing-device surface to let a user drop and drag polygon vertices — something the existing Typer/questionary/Rich terminal stack can't provide. We considered a native GUI toolkit (Qt, Tkinter), a curses-based terminal grid editor, and a local HTTP server serving an HTML5 canvas. We chose the local web app: it needs no new heavyweight GUI dependency, is cross-platform for free via the system's default browser, and keeps Cairo/rendering entirely server-side — the browser is purely an input surface that posts a vertex list back to the CLI process, which validates (simple-polygon check) and writes it to the shapes file before exiting.

This also means custom shapes needed somewhere to persist between the editor run and later render/overlay invocations. Every other file-backed concept in this tool (presets' `--config`) is explicit-flag-only with no default, because built-in presets already cover the common case. Custom shapes have no such built-in fallback, so we deliberately deviated from that convention: the shapes file defaults to `~/.config/nltl-viz/shapes.yaml`, with `--shapes-file` as an override — otherwise a shape drawn once would require re-passing a path on every subsequent render.
